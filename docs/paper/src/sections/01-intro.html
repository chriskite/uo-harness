Introduction

On a Sunday evening in late September 2026 the owner of this repository typed a one-paragraph prompt into an AI coding agent: build an agent harness that plays Ultima Online Outlands, research how, and present a plan. Ten days and 389 commits later, a character named Outland Dan was recalling out of a guild house rune library to a forest a few hundred tiles away, chopping trees as fast as the server allows, running from air dragons, fleeing player-killers, carrying boards home to a rented room, and reporting all of it to an LLM overseer that styles itself after Hawkwind the Seer. Nobody modified the game client.

Goal: create an AI agent harness that plays Ultima Online Outlands. […] Research how best to accomplish this and present a high level plan.

— the founding prompt, 2026-09-27 19:18 (laptop session log)

This paper is the long-form record of how that happened: what we built, the techniques we borrowed and invented, the many things we got wrong first, and what the numbers say so far. "We" means the owner and the fleet of coding agents he directed; the split of credit is itself one of the subjects ().

Why this is harder than it sounds

Ultima Online (1997) is one of the first graphical MMOs: an isometric tile world (Outlands' main map is 10,752 × 6,144 tiles; stock UO's is 7,168 × 4,096), skills that rise with use, and full-loot player-versus-player. Outlands is a popular free shard (a privately run server) with its own client fork. has the details.

Game bots are old news, and Ultima Online has had macro assistants since the last century. What made this project interesting is the combination of constraints we accepted (some on day one, some along the way):

  • The client is a fortress. The Outlands build of ClassicUO is compiled ahead of time to native code (NativeAOT). There is no .NET intermediate language to decompile, no runtime to hook, and no sanctioned plugin surface. We decided early never to inject into it, never to patch it, never to send synthetic keyboard or mouse input to its window, and never to write a byte into its install directory.
  • The server must see a normal client. Everything the harness does has to arrive at the server as packets the stock client could have sent, in the order and shape it sends them, interleaved with the human's own traffic on the same connection.
  • The agent must never reveal itself. No injected speech that mentions harnesses, testing or AI; a standing rule since day two AGENTS.md Constraint 4.
  • The world is hostile. Outlands has full-loot PvP, thieves who pick pockets, monsters that wander into lumber groves, harvesting CAPTCHAs, and staff who watch for unattended play.
  • The code has to explain itself. Every engineering finding is written down and pushed before a session ends (Rule 0), so that a fresh agent with no memory of the conversation can carry on. That rule is why this paper could be written at all.

The system at a glance

The architecture we settled on is a man-in-the-middle of the most boring kind: a localhost TCP proxy (). A WinDivert NAT quietly redirects the stock client's game connection to the proxy, which decrypts both directions and decompresses the server's, keeps a packet-built world model, and lets deterministic Python "runners" inject their own actions into the client's stream. A SQLite memory store records every event and doubles as a message bus. An LLM overseer, the Seer, sits outside the inner loop: it is woken at important junctures, reads the store through a small CLI, and decides what job to run next, while the runners do the reflexes.

Two design choices carry most of the weight. First, the proxy never originates a server-visible packet of its own: it forwards the client's traffic, it writes the agent's packets in the stock client's exact shapes, and the only thing it ever withholds is a duplicate reply to a target cursor the agent already answered. The fiction that keeps the client's screen honest (for example, a fake "you can't walk there" re-anchor after an agent step) is fabricated toward the client only. Second, the LLM decides what to do next, and deterministic code does it. The LLM picks the job, starts and stops it, and handles the situations the runners report; chopping, walking, fleeing and storing are deterministic controllers with typed failures. An LLM making those moment-to-moment moves would be slow, expensive and, as one dungeon fight demonstrated, fatal ().

What this paper contributes

Most of what follows is engineering narrative, but a few pieces are, we think, worth stealing:

  1. A memory the whole system shares. One SQLite store that every component writes into and the overseer reads from: 2.1 million events, walk and harvest memory, trips, junctures, chat, and a knowledge table with hybrid semantic search on the GPU that also holds facts vetted from the community Discord. Beside it sit a local triage model (Laya) and the raw Discord corpus in its own database (, ).
  2. Two senders, one character. A proxy that lets a human and an agent drive the same avatar at once, on one shared walk sequence and fast-walk key ladder, with client-only fabrications that keep the client's view consistent (). Re-framing all 65 non-empty captured client streams offline with the final length table (515,303 packets) gives zero client-to-server framing desyncs, and live the proxy logged none after the 09-29 length-table fix (47 sessions, about 82 h); before that fix two targets were misframed without being flagged.
  3. A packet-built world model with real 3-D pathfinding from the client's own map files, houses included, and rune libraries read without ever casting a spell ().
  4. A loop learned from demonstration and hardened against the shard's hazards, with a CAPTCHA solver that went 57 for 57 (), then made self-optimizing: Thompson sampling over lumber spots, competing death, sent-home and theft hazards, and a renewal-reward trip size (, ).
  5. Survival engineering measured against an actual player-killer: recall-on-sight in about two seconds, a thief guard, keep-away from monsters ().
  6. An LLM overseer on a database bus: junctures, a CLI, a phone bridge and a vetted knowledge base distilled from the community Discord (, ).
  7. A field report on building it with AI agents: 568 human prompts, 54 top-level sessions and 92 subagents, in which the owner set the goals and made the product and risk calls, and the agents worked out most implementation designs within them inferred (the record holds 32 "user decision" or "(user, …)" attribution markers in docs/NOTES.md and 19 commit messages with such a marker at ee59524, but no tally of agent-originated decisions), including a loop where the Seer's reports from the field became runner fixes within the hour ().
