Packet, port and file-format reference

The protocol facts, packet ids, local ports and file formats the harness depends on, in one place. The chapters explain how each was found; this appendix is for looking things up.

All values are for the Outlands fork of ClassicUO (client 1.0.2.544, patched to 550 on 2026-09-28 without changing the wire), protocol version 12. Multi-byte packet fields are big-endian. The proprietary .uoo data files are little-endian. Sources are docs/PROTOCOL.md, docs/CIPHER.md, docs/MOVEMENT.md, docs/MAP.md and docs/MEMORY.md, by way of research briefs 02 and 03. The wire in brief

Ports and endpoints

Client → server packets the harness sends

Every agent packet is built by harness/actions.py in the byte layout the stock client uses for the same gesture, padded to the client's length table. The counts are agent-originated packets across all 69 desktop session logs. For scale, the human's client sent 251,770 0xFF packets over the same logs, most of them keepalives.

Builders also exist for vendor sell (9F) and prompt and text-entry replies (9A, AC, C2). The login (91), character select (5D) and the keepalive are always the client's own.

Server → client packets the harness reads

The world model has handlers for 46 S2C ids and 17 C2S ids. Every parsed id parses on every real packet in the 18 reference captures. The table groups the ones that matter by what the harness does with them.

The proxy also writes three kinds of packet to the client alone, encoded with the session key, which never reach the server. A 0x21 re-anchors the client's display after an agent step. A 0x6C cancel takes down a cursor the agent already answered. A 0xBF sub 4 closes a gump the agent already answered. Over the 69 desktop logs that came to 45,136, 5,688 and 1,875 packets respectively brief 02 §3.3. Why these exist is told in .
